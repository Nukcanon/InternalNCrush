## 기능과 그래픽 설정

웹에서도 킬 리플레이, 봇 전투, 연습장, 모든 모드·전장, 멀티플레이, 무기와 스킬을 유지합니다. 충돌·총격·폭탄·피해 판정이나 연막의 전술적 범위를 그래픽 품질에 따라 바꾸지 않습니다. 직접적인 모델/아트 복제가 아닌 자체 카툰 스타일이며, XIII와 동일한 최종 화면이라는 의미는 아닙니다. Deadshot 공식 페이지는 이 환경에서 게임 로딩 오류를 표시하여 실제 플레이 비교는 하지 못했습니다.

| 설정 | Windows 낮음 | Windows 중간·기본 | Windows 높음 | Web 자동 초기값 |
|---|---|---|---|---|
| 광원 | 고정 명암 | 주 광원 | 주 광원 + 보조 최대 4개 | 고정 명암 |
| 실시간 그림자 | 끔 | 끔 | 1024, 개별 설정 2048 가능 | 끔 |

| 안개 | 끔 | 끔 | 맵 안개 | 끔 |

Windows 신규 프로필은 중간 설정입니다. 기존 Windows 사용자의 개별 저장 설정은 존중합니다. 그래픽 항목은 설정에서 조절할 수 있습니다. 방향 광원 그림자는 광원에서 비활성화하고, GLES에 0 크기의 방향 그림자 아틀라스를 넘기지 않습니다.

### 추가 요청: Web 자동/수동 그래픽

Windows 신규 프로필은 중간, Web 신규/이전 프로필은 자동입니다. Web은 자동·낮음·중간·높음·사용자 설정을 제공합니다. 광원, 그림자, MSAA, 장식 효과, 안개, 선명도, FPS 상한을 직접 선택할 수 있습니다. 직접 바꾸면 자동 조절을 멈추며, 자동 복원 버튼으로 돌아갈 수 있습니다. Windows와 Web의 품질 값은 별도로 저장합니다.

자동은 전투 시작 후 8초를 기다리고, 3초 구간의 실제 렌더 프레임을 관측합니다. 느린 구간이 두 번 연속이면 효과를 먼저 낮추고, 최저 효과에서도 느리면 선명도를 85%로 낮춥니다. 여유 있는 구간이 다섯 번 연속이면 선명도부터 복원합니다. 변경 후에는 18초간 추가 변경을 막아 잦은 품질 왕복을 줄입니다. 설정 화면·리플레이·다른 탭에서는 품질을 학습하지 않습니다. 선택한 30 FPS 제한은 목표값에 반영합니다.

자동/수동 어느 쪽도 가까운 모델의 원본 형태나 카툰 색상, 기능을 단계별로 깎지 않습니다. 원거리 LOD는 고정된 메시의 화면 크기에 따른 렌더링 기능입니다. 원본 근거리 메시 자체를 심하게 단순화한 메시로 교체하던 기존 웹 준비 단계는 제거했습니다.

## 약한 탄도

총기 산탄과 포탑 기관총에 공통으로 적용합니다. 중력 4m/s², 기준 속도 300m/s이며, 풍향·공기저항·실시간 탄환 RigidBody는 추가하지 않습니다. 호스트가 발사 시 최대 12개의 짧은 선분으로 곡선을 검사하며 첫 충돌에서 중단합니다. 미사일과 수류탄은 기존 이동 규칙을 유지합니다.

| 거리 | 기준 낙차 |
|---|---|
| 25m | 약 1.4cm |
| 50m | 약 5.6cm |
| 100m | 약 22cm |
| 200m | 약 89cm |

기존 근거리 총구 보정과 벽 뒤 총구 차단 판정은 유지합니다. 먼 표적을 빗나가면 그 표적 앞에서 탄환 검사를 끝내지 않고 실제 곡선의 첫 충돌까지 검사합니다. 네트워크에 탄환 물체를 추가하지 않습니다. 수치는 밸런스 시작값이며 플레이테스트 후 조절할 수 있습니다.

## 검증 상태

- 소스·빌드 GDScript 95개와 수정한 테스트 10개: `gdparse` 문법 검사 통과. Godot 자체 타입 검사나 셰이더 컴파일 결과는 아닙니다.
- 수정한 GDScript 테스트의 문법 검사 수행. 포탑 접근/교체/강화, 모바일 토글·안내·킬 피드, 탄도 충돌/낙차, 카툰 메시 예산, 낮은 물리의 사망 연출, 벽 뒤 자동 발사 차단 테스트 추가/갱신.
- Web 자동 정책 테스트 추가: 단발성 지연 무시, 효과 우선 조절, 85% 하한, 선명도 우선 복원, 왕복 억제, 30 FPS 제한, 사용자 설정과 Windows 설정 분리. 이 테스트도 엔진에서는 아직 실행하지 못했습니다.
- `python3 web/prepare_lightweight.py`: 성공. 준비본에 리플레이·연습장·봇·탄도 코드와 연막 에셋이 남고, 사진 피부 에셋은 제외되는 것을 확인.
- Python 변경 파일 컴파일과 `git diff --check`: 통과.
- **미실행**: Godot 엔진 테스트, 셰이더 컴파일, 게임 화면 확인, Windows/Web 내보내기, 혼합 플랫폼 경기, GTX2060 및 스마트폰 FPS/프레임 시간 측정.
- **차단 사유**: Godot 공식 다운로드/소스 획득은 연결 시간 초과 또는 502. 두 GitHub 저장소 원격 조회와 쓰기 가능 여부 확인도 502. 이 세션에 GitHub 전용 읽기/쓰기 도구가 노출되지 않음.

성능 개선률, 최종 다운로드 용량, 최종 삼각형 수를 측정한 것으로 주장하지 않습니다. 기존 1.1.4의 검증 보고서를 이번 변경의 실행 결과로 재사용하지 않습니다.

## 실행 검증과 1.1.4 덮어쓰기

사용자의 후속 요청에 따라 버전은 1.1.4로 유지하고 기존 릴리스 파일과 사이트를 교체하도록 구성했습니다. 앞서 만들었던 검증 전용 ZIP 대신 최신 1.1.4-overwrite.zip 묶음을 사용합니다.

1. [MANUAL_UPLOAD.md](MANUAL_UPLOAD.md) 순서대로 게임 저장소 main에 수정 파일을 올립니다.
2. Build and replace Internal N Crush 1.1.4가 엔진·기능·네트워크 검사와 Windows/Web 내보내기를 수행합니다. 모두 성공한 main 빌드만 기존 Windows/Web 릴리스 파일을 교체합니다.
3. 이어서 사이트 저장소 main에 해당 묶음을 올리면 새 릴리스의 ZIP 해시, 파일별 해시, 소스 커밋을 검증하고 play/와 링크를 갱신합니다. Pages 빌드도 요청합니다.
4. 실제 브라우저와 스마트폰에서 이동·조준·슬라이딩·자동 발사·폭탄·리플레이와 FPS를 확인합니다. CI 통과만으로 실기기 성능이나 모든 그래픽 결과를 보장하지 않습니다.

웹은 빌드 소스 커밋을 포함한 파일 이름으로 내보내 같은 1.1.4 이름의 캐시가 새 JS/WASM/PCK와 섞이는 것을 줄입니다. 사이트의 링크에도 새 웹 ZIP 해시를 붙입니다.

이전 커밋과 태그는 유지합니다. 1.1.4 태그 자체를 강제로 옮기지 않으므로 새 실행 파일의 정확한 소스는 릴리스의 WEB_RELEASE_v1.1.4.json에 기록된 커밋으로 확인합니다. 기존 NAS 설정 패키지는 교체하지 않습니다.

새 배포 스크립트는 잘못된 ZIP 해시, 파일 내용, 경로, 소스 커밋을 거부하고 기존 웹 파일을 유지하는 로컬 검사를 통과했습니다. 자동 배포 전체를 GitHub에서 실행한 결과는 아직 아닙니다.
