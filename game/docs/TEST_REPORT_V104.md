## Windows 그래픽 클라이언트의 접속 회귀

배포 EXE 검사에서 메뉴 봇 배경을 닫은 뒤 `Node not found ... SubViewport` RPC 오류가 반복되는 것을 발견했다. `menu_demo.gd`의 종료 처리가 공유 MultiplayerAPI를 삭제되는 배경 경로에 재등록하면서 실제 경기 RPC 기준 경로를 바꾸고 있었다. 해당 경로의 override만 `null`로 제거하도록 수정했다. [Godot 4.4.1의 경로별 해제 구현](https://github.com/godotengine/godot/blob/4.4.1-stable/scene/main/scene_tree.cpp#L1542)을 확인했다.

메뉴 생성/제거 두 회 동안 오프라인 API 분리와 기본 RPC 경로 보존을 검사하는 4개 회귀 항목을 추가했다. 기존 headless 검사에서도 실제 메뉴 배경 생성을 명시적으로 실행한다. 로컬 Windows에서 화면 없는 서버 및 일반 게임 방장과 그래픽 클라이언트 조합 모두 오류 없이 두 명 전투 상태로 연결됐다.

Windows 배포본의 headless 파일 로그는 종료 전까지 버퍼에 남을 수 있다. ZIP 검사기는 로그 문구 대신 해당 테스트 프로세스가 소유한 실제 UDP 소켓으로 서버 준비를 확인한다. 재사용 가능한 검사기는 `windows/verify_build.py`이며, 사용자 게임을 종료하거나 프로필을 저장하지 않는다.
